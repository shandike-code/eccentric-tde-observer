## 1. 已修复的实际缺陷

| 问题 | 修复与验证 |
| --- | --- |
| `complete_round` 给账本传的是辐射端点字典，字段为 `input_sha256/output_sha256`；`run_ledger` 读取 `sha256`，会抛 `KeyError`。即便改成辐射态 SHA，也不等于反馈 NPZ SHA。 | 先从正式反馈摘要和 manifest 校验两个 NPZ，持久化独立 `feedback_claims`，再交给账本。跨函数测试走实际 `complete_round → run_ledger`。 |
| 端点审计记录的是 map 输出；正式反馈实际消费 map 输入。 | `endpoints_claim` 固定为两个 input path/SHA，核对相邻性、正式协议来源和反馈 manifest。大态 SHA 来自已提交记录，物理适配器负责实际大态验证，不把这一步描述成重新读取全部 `.dat`。 |
| 根目录缓存协议可能来自旧反馈对；共享 template 会被后续轮次重新生成。 | 每轮拥有 `inputs/`、trial 副本、template 和协议；不读取或删除根目录旧协议。只在协议内容完全一致时允许同轮恢复，拒绝不同内容覆盖。 |
| map4/map8 已落盘、pending 尚未落盘时中断，恢复可能先跑新 map 或直接结束预算。创建轮次目录到登记 pending 之间也有中断窗口。 | 在运行新 map 前重建恰好到期的反馈；已经错过且槽位可能复用的边界停止检查。先登记轮次归属，再创建目录。新增中断恢复测试。 |
| 最后一张 map 接受后，末尾预算判断仍可能覆盖接受状态。 | 预算完成只作用于正常辐射状态；新增 map8 接受测试。 |
| 只恢复账本时未重验已完成反馈；完成轮次摘要落盘后状态未提交时恢复缺乏幂等检查。 | 重验协议、非辐射小输入、摘要、反馈 NPZ 与 manifest；账本须匹配 trial 和旧时间层输入。相同完成摘要允许重入，不同内容拒绝覆盖。 |
| 重启监督器会隐式重新提交上次失败的作业。 | 新参数 `--retry-failed-job JOBID` 必须精确匹配已检查原因的失败作业；每个新的失败单独处理。它是执行者检查后的恢复标记，不要求用户逐次授权。 |
| 运行声明漏检新加入的诊断源码；全零反馈会触发 `nanargmax` 或非有限诊断。 | 比较源码集合及 SHA；正式零/零稳定性沿用原验收定义为 0，未定义占比/相消放大写 null，没有虚构热点，不加 floor。 |

修改限于 `diagnostics/`、测试与交接说明；历史 `src/`、`scripts/`、`hpc/`、旧数值结果、物理 dt、布居约束与能量定义均未修改。

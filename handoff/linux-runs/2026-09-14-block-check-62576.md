## 5. 根因与处置

**根因：`submit.sh` 对 block-check 的默认墙钟 `00:30:00` 在此平台不足。**

`job.sbatch` 含 `--signal=B:USR1@600`，Slurm 在墙钟到点前 600 秒（即 30 分钟作业的第 **20:00**）向 batch step 发 SIGUSR1；`job.sbatch:14` 的 trap 将其转发给子进程。但 `hpc/check_block.py` **未安装 SIGUSR1 处理器**，默认动作即终止。

**处置：** 按 `hpc/README.md:135`（「该检查不续跑；需要重做时使用 `TDE_RUN=outputs/hpc/block-check-2` 创建新目录」），以更大墙钟重跑：

```bash
TDE_RUN=outputs/hpc/block-check-2 TDE_WALLTIME=01:00:00 bash hpc/submit.sh block-check
```

→ 作业 `62585`，墙钟 `01:00:00`（USR1 推迟至 50:00，相对约 21 分钟的实测总耗时余量充足）。

**未修改任何源码、容差或配置。** 第一次的目录与失败报告按 `AGENT_TASKS_ZH.md:122`「失败时保留配置、输入与失败报告」保留在原处。

## 6. 平台问题记录

- `sacct` / `sstat` 对本集群**返回空**（`slurmdbd` 为 active 但不落数据）。运行中状态只能靠 `squeue` / `scontrol show job`，作业结束后 `scontrol` 仍可查 `JobState`/`ExitCode`。**峰值 RSS 与 CPU 时间无法从调度器获取**，需由 worker 自报（`mapped.json` 的 `peak_process_rss_mib` / `wall_runtime_s` 已提供，可满足验收要求）。
- 稀疏文件**逻辑大小 29 GiB / 实际占用约 390 MiB**。部分平台 quota 按逻辑大小计费，本平台 `quota` 命令不存在，未能确认。

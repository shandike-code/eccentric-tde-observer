## 必须先修的诊断与运行问题

下列行号均对应原提交 `6423e4c`。

### P1：深度映射错误，空间定位结论需撤回

`diagnostics/material_energy_ledger.py:237` 用 `per_depth.reshape(128, 32)` 将辐射子胞贡献归入所谓物质层。

实际适配器 `scripts/phase7b9_formal_feedback_pair_adapter.py:593` 使用 `reshape(256, 16, ...)`：4096 子胞对应 **256 个全柱 parent 层，每层 16 子胞**，`half_*` 取 parent 的前 128 层。镜像关系是前半柱与后半柱逆序相对，不是相邻两个 parent 合成一个物质层。

复现：只在子胞 `[96*16:97*16]` 放入加热变化，真实 parent 层号是 96，而账本 `top_layers[0]` 返回 **48**。

因此旧报告的“贡献最高物质层 60、67、71……”“cell 96 只占 0.109%”“加热变化与物理域失败空间不重合”均不能保留为已证实结论。报告所说两网格没有对应关系也不正确。正确聚合应先得到 256 层贡献，分别报告前半柱、后半柱，若按镜像折回 128 层则明确使用 `front + back[::-1]`。对已经包含宽度权重的分子贡献求和，不再次乘宽度。

这一错误位于诊断定位，不在原适配器生成 `half_*` 或原求解器物质能量更新中；不能据此宣称既有全部 map 作废。

### P1：归档重试会覆盖证据，搬移后原路径失效

`interval_diagnostic.py:117–126` 对文件无条件 `os.replace`，对已有 `feedback/` 目录先 `shutil.rmtree`。`:133–136` 又把根目录中所有工件都假定为上一轮遗留，未核验所属协议或是否为当前轮部分完成态。

复现：同一目标归档已有 summary 和 `feedback/old`，根目录出现另一组工件后再次归档，原 summary 被替换、`feedback/old` 被删除。manifest 中 `feedback_artifact_path` 仍指向 run 根目录，搬移后该引用不存在；冻结 protocol 的 template 路径也有相同问题。

新轮次应从创建时就拥有固定独立的 protocol、工作区、结果路径和清单。已完成归档只读；同内容可验证后幂等返回，不同内容必须报错。已有历史归档不能改写旧协议来“修哈希”，应另建带旧路径、新位置与 SHA 的迁移索引。辐射槽位会循环复用：小工件可重定位验证，不得承诺旧大态始终还能按原槽位重读。

### P1：账本失败仍记录完成

`interval_diagnostic.py:152–155` 忽略 `os.system` 返回码，也不检查 JSON 是否生成、能否解析、输入哈希是否对应本轮。

复现：模拟账本子进程返回非零 256，`feedback_round` 仍追加已完成轮次；模拟反馈门通过时仍返回 `accepted=true`，但 ledger 文件不存在。该复现没有伪造物理反馈，只证明控制流没有处理账本失败。

改为列表参数的 `subprocess.run(..., check=True, cwd=ROOT)` 或等价直接调用；验证输出及来源后才提交完整轮次。物理反馈已完成而账本失败时，保存独立的“诊断未完成”状态，恢复只重做缺失步骤。不要把账本完成作为新增物理门，也不要把缺少账本写成完整诊断交付。

### P1：恢复先跑新 map，可能丢失待做的反馈端点

`interval_diagnostic.py:205–218` 在 map 循环之后才检查反馈。若 map4 已完成、反馈尚未完成，重启默认命令会先推进 map5，再因不是 4 的倍数跳过反馈。三槽位轮换可能覆盖原反馈端点。`maps-per-job > 1` 还会跨过中间的反馈边界。

复现：持久态 `history=4, rounds=[]`，重启时 mock 事件只有 `new_map`，没有 `feedback`。

应持久化 pending feedback 的轮号、端点路径和 SHA，在任何后续 map 前恢复；每次 map 完成后检查轮次边界。模拟反馈中断、归档中断、最终 state 写入前中断，验证同轮恢复不重复提交且不会替换端点。

### P1：停止条件没有传到实际分块循环，终态优先级错误

- `interval_diagnostic.signal_stop` 只改自己的 `STOP`；`pipeline.batches` 查的是 `pipeline.STOP`。复现信号后两者分别为 `True/False`，因此“当前块 batch 后停下”没有实现。
- `feedback_round` 的 accepted 返回值被 main 忽略。模拟 map4 反馈全通过后，state 仍为 `radiation`，监督器可继续提交。
- map8 设置 `resource_gate_failed` 后，main 仍可调用反馈，并最终覆盖为 `diagnostic_round_complete`。已用 mock 复现终态覆盖。

需要共享/传递 stop 状态并验证真实 batches 不再发新 worker。资源失败优先停止；已通过一个物质步应成为终态；map 预算只控制新 map，不应阻止最后一对反馈恢复。不要把预算完成覆盖到故障或接受状态上。

### P2：诊断版本和执行参数没有冻结

`pipeline.prepare` 只收集 `src/`、`scripts/`、`hpc/` 的 Python 文件。新 seed 工具复制该 sources 列表，新 driver 验证的仍是旧列表；本轮实际执行的 `diagnostics/` 文件没有被固定。`feedback-every` 等 CLI 参数也未进入不可变诊断协议。

在 diagnostics 自己的独立运行声明中固定实际驱动、账本、播种/监督脚本、sbatch 的 SHA、Git 提交及执行参数，运行时核验。不要补改既有 run 的冻结配置；为修正版创建新命名运行。启动种子需核对来源 state/manifest 的已提交 SHA、尺寸/布局及同一物质候选，而不是仅将任意现存文件重新哈希后称为可信种子。

## 账本输出还需修正的口径

1. `material_energy_ledger.py:178–179` 的 `old_hydrogen/old_helium` 实际填入 `new_h/new_he`。应同时输出真实 old/new 数组及逐层差。
2. `:152–156` 先按绝对热能选择最差层，再计算该层相对缺口，不等于全层最大相对缺口。分别给出绝对最差层和相对最差层、相应索引及值；不要改选“好看的”指标。
3. `:221–224` 对多分量率取最大分子、最大分母和最大比值，三者可能来自不同分量。合成例得到分子 4096、分母 409600、报告 ratio 0.5；分子/分母却是 0.01。保留所有分量，或输出最大比值所属同一分量的分子/分母。标量加热门不受这一特定展示问题影响。
4. 全零变化、零净量时，累计贡献与相消比有除零风险。明确零信号/未定义的语义，用 null 和状态说明；JSON 用 `allow_nan=False`，不得加任意 floor。旧时间层、反馈源、网格关系从已验证协议读取，不能仅依赖硬编码路径。
5. “相消因子中位数 × 全局最大归一化吸收变化”不是正式加热加权指标的等式。局部的相减与敏感性可说明机制；不能把不同聚合尺度的数相乘当成定量因果证明。
6. 本次复核确认账本调用的 `rmf.charge_neutral_backward_euler_step` 和物质响应默认二分次数都为 96；不是默认参数不一致。测试应直接比较完整物质响应的中间量/正域输出，避免只验证手写拆分。

## 科学解释与后续预算

报告的“原算子残差下降、负热能缺口改善”仍是已有观测，但具体数值在本次未独立重算。净冷却主导 cell96 缺口的算术解释不因归层展示错误自动失效。先用已有 feedback NPZ 重算修正版诊断，再更新相应结论。

“几何衰减永远到不了零”不适用于直接判断剩余热能是否穿零：它的极限符号未知。两个不同迭代阶段的收缩比也不能证明“越接近固定点一定越慢”的普遍规律。发射项固定源于当前固定物质候选及其系数，不能简单等同于热力学更新所用旧时间层。

修复及回放通过、未发现原反馈输入或物理记账错误后，继续固定 0.0625 候选的方案仍合理：最多 8 张新增 map，每 4 张做一次相邻两态反馈，目标是获得可评估的物质响应/噪声/收缩指标。所有原门保持。若端点都进入正域，即使加热门未过也计算诊断，但不接受候选；若稳定反馈与噪声控制通过后物质响应或收缩仍失败，再评估回溯/闭合。

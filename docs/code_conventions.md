# 代码与 Markdown 写作规范：物理可读性、中文注释和公式定界符

本项目的代码首先服务于可验证的理论建模。以下规则适用于后续新增和修改的模块。

## 1. 中文注释

- 关键物理公式、坐标约定、积分测度、守恒量和拒绝域附近必须有简洁中文注释；
- 注释解释“为什么采用这个式子或检查”，不逐行翻译 Python；
- 公共函数的 docstring 可保留英文接口说明，但核心推导旁必须有中文提示；
- `[L] / [A] / [V] / [O]` 的物理归属主要写在阶段文档和报告中，代码注释可在容易
  混淆的位置标出。

## 2. 物理状态处理

- 非有限量、非正密度/温度/频率、超光速、视界内点和不存在热化层的状态直接报错；
- 禁止用 `nan_to_num`、无物理依据的 `clip`、任意 floor 或重新归一化掩盖失败；
- 若某个近似不能守恒，应输出明确残差并把结果降级为审计量，不能称为预言；
- 所有新增闭合必须说明输入、适用域、失效条件和可观测后果。

## 3. 数值结构

- 源模型、局域大气、几何/可见性、频移和观察者积分保持模块化；
- 优先使用可单独测试的小函数；性能优化只在基准确认瓶颈后进行；
- 周期异常角使用 $[0,2\,\pi)$，不重复端点；
- 输出保留物理单位，实际 $F_{\nu}$ 不用任意归一化替代；
- 重要扫描同时写出 CSV、JSON 报告和可视化，图必须经过视觉检查。

## 4. 必要验证

- 保留 $e \to 0$、$g \to 1$、黑体极限、纯吸收/纯散射边界和能量积分极限；
- 网格、射线和频率积分需要独立收敛审计；
- 解析事实、文献事实、代码验证和工作假设必须在报告中分开陈述。

## 5. 第三阶段新增约定

- H/He Saha 电离与束缚—自由吸收只称为 LTE 连续谱审计；没有统计平衡、金属原子库和
  非灰辐射平衡时，禁止标成 NLTE 环带大气；
- 偏振输出必须同时保存 Stokes $I,Q,U$，不能只保存偏振度；当 $I=0$ 时偏振无定义，
  直接拒绝该频点，不把 $0/0$ 改写为零；
- GR 传递必须把像平面 Jacobian 与频移 $g$ 分开保存，并在 $M/r \to 0$ 数值回收
  Newtonian 投影；弱场近似不得命名为 Kerr ray tracing；
- 再处理模块只能输出质量、能量、动量、光深和扩散时间的约束面。除非裸盘失败且高能
  种子谱、离化态与守恒预算均已给定，不实例化自由盘风；
- 图中若包含超出物理闭合域的形式曲线，标题、阴影或图注必须直接标出，不依赖正文补救。

## 6. 第四阶段新增约定

- 静态大气表必须同时声明 $T_{\rm eff},m_{0},Q,\mu,\nu$ 定义域和 provenance；任何轴外查询直接
  拒绝，禁止外推或夹到边界；
- 对动态 ZO 柱必须同时保存 $Q_{\rm tidal}$、$Q_{\rm pressure}$ 和准静态比率，不能只选一个较方便
  的重力值；
- 真实仪器响应与理想 top-hat 必须在变量名、图题和报告中区分；
- 相位光变若没有绝对进动解，时间轴写成 $t/P_{\rm prec}$，不得擅自指定天数；
- 一个倾角只有在整圈相位都通过局域发射角和表面几何检查后，才能进入有效图谱。

## 7. 第五阶段新增约定

- $F_{\nu}$ 转 $F_{\lambda}$ 必须显式包含 Jacobian，并用 $\lambda F_{\lambda} = \nu F_{\nu}$ 与积分
  守恒双重验证；图轴标签必须写明每 Hz 或每 Angstrom；
- 红移、光度距离和前景消光是独立算子，参数与来源分别保存，不允许把距离归一化或尘埃
  调色吸收到源模型；
- 进入代码的仪器响应必须保存来源、版本和有效日期；响应域外不外推；
- 演示红移、消光和宇宙学参数必须标明“非事件拟合”；宿主消光无独立先验时默认关闭。

## 8. Markdown 公式与写作格式

- 本节只约束写入项目文件的 Markdown。聊天回复使用 GPT 客户端默认数学排版，不要求在
  可见回复中刻意展示美元符号定界符；聊天的完整要求见
  [[eccentric_tde_observer/docs/chat_output_standard|项目聊天输出规范]]。
- Markdown 文件内的小公式、单个变量和正文中的短关系一律使用单美元符号包裹，例如 `$T_{\rm eff}$`、
  `$g=\nu_{\rm obs}/\nu_{\rm em}$`；公式定界符与公式内容之间不额外留空格。
- 数学环境中的希腊字母必须写成 LaTeX 命令，例如 `$\Sigma$`、`$\tau$`、`$\kappa$`、
  `$\nu$`，禁止写成 `$Sigma$`、`$tau$`、`$kappa$`、`$nu$`。
- 多字符或整体下标必须用大括号圈起；描述性下标使用直立体，例如 `$T_{\rm eff}$`、
  `$z_{\rm ph}$`、`$F_{\nu,\rm obs}$`。禁止 `$T_eff$`、`$T_{eff}$` 和 `$F_nu_obs$`。
- Markdown 文件内需要独立成行的公式一律使用双美元符号。开始和结束的 `$$` 各自独占一行，公式块前后
  各保留一个空行，例如：

```markdown
$$
F_\lambda=F_\nu\frac{c}{\lambda^2}10^{-8}.
$$
```

- 项目 Markdown 文件禁止使用反斜杠圆括号或反斜杠方括号作为公式定界符；同一项目中不混用
  多套公式语法。
- `aligned`、`cases`、矩阵和多行积分必须放在 `$$` 公式块内部，不把大公式强行塞入正文。
- 反引号只用于代码、字段名、文件名和不需要数学渲染的字面量；数学变量不能因为方便而
  写成代码样式。
- 货币美元符号必须转义为 `\$`，避免被误判为未闭合公式。
- 公式出现前先定义变量；公式之后必须说明它在当前模型中的作用、证据归属和适用域，
  不用“显然”“容易得到”等表达跳过必要逻辑。
- 修改 Markdown 后运行 `uv run python scripts/normalize_markdown_math.py`；命令无输出且退出码为
  0 才表示上述机械格式检查通过。需要批量修复时先审阅 diff，再使用 `--write`。

## 9. 第六阶段新增约定

- 谱线逻辑保持在独立 `line_response.py`，不写入连续谱模块；
- delta 线的频率积分显式使用 $g^4$，并用直接面积分验证；
- 正式线核只消费 corrected 曲面三角形或像平面面积，禁止调用 pre-Erratum 权重；
- 只允许 uniform、ZO 热功率和完全电离 EM 三种受控权重，不增加自由 $r^{-q}$；
- 峰数分类标为 `[A-classification]`，连续输出峰间距、峰比、质心、偏度和谷深；
- 归一化线核不指定等效宽度，不称为 Halpha、Hbeta 或 He II 的绝对光度预言。

## 10. Phase 7A 新增约定

- 静态环带输入必须显式记录 $T_{\rm eff}$、$m_{0}$、$Q$、原子模型、软件版本和数值控制；
- TLUSTY unit 13 的 $H_{\nu}$ 必须转换为 $F_{\nu}=4\pi H_{\nu}$，并检查频率积分能量残差；
- 灰初始化、未收敛结构或缺少谱文件的运行一律保留为诊断/失败，不能进入大气谱表；
- 代表柱只能从真实 ZO 网格点选择；抽样权重必须保留 corrected 面积来源，不能使用
  pre-Erratum 测度；
- LTE 到 NLTE 的重启顺序是数值可行性路径，不得把 LTE 控制或灰初值称为最终 NLTE 大气；
- 官方控制通过只验证软件链；实际柱失败不得夸大成“静态解不存在”，应标为 `[V/O]`。
